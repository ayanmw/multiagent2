# 代码评审清单（code-review）

Reviewer 子代理只能 read/grep，不能写或执行；本清单用于系统化挑错，结论先行。

## 安全性（最高优先级）
- 外部输入是否流入 shell / SQL / 命令（必须经 `executor.SafeExecutor` 与 `resolveSafePath` 路径校验）？
- 是否泄露密钥/Token（禁止入库本地绝对路径、作者用户名、明文密钥）？
- 高危命令（`rm -rf /`、`git push --force` 等）是否被策略拦截或进入人工检查点？

## 正确性
- 边界条件、nil/空值、并发竞态（特别是复合唯一索引的并发插入）。
- 错误处理是否吞掉 `err`（`err != nil` 必须处理或显式 return）。
- 资源释放：`defer Close`、连接/文件句柄是否泄漏。

## 可读性与规范
- 命名是否表意；函数是否过长（>60 行考虑拆分）。
- 是否复用既有 DTO/抽象（如经 `internal/engine` 层封装框架，业务不直连框架）。
- 魔法值是否提为配置/常量。

## 测试
- 新增逻辑是否有单测；CGO 缺失环境下的 DB 用例是否用 `t.Skip` 而非弱化。
- 是否遵循「先 build/vet/test 再提交」。

## 输出格式
- 结论先行（`✅ 通过` / `❌ 问题`），逐条列出问题并给修复建议与 `文件:行号`。
