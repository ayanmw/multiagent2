# CodeAgent 平台 — 需求整理与总体规划（V0.1 草案）

> 基于 trpc-group/trpc-agent-go 的企业级多 Agent 协作 CodeAgent 平台
> 状态：待评审 | 日期：2026-07-28

## 1. 原始需求整理

| # | 需求项 | 说明 |

## 2. 需求补全建议（原始需求未覆盖、建议纳入）

**建议 P0（首期必须）**
- **N1 用户与权限**：登录认证（JWT）、角色（Admin/Developer/Viewer）、API Key 管理（供 CLI 用）。企业级底线。
- **N2 会话与项目管理**：Workspace（代码工作区）→ Session（对话/任务）两级模型；会话持久化、可恢复、历史回放。
- **N3 流式输出**：SSE 流式推送 Agent 事件（token 级输出、工具调用、子 Agent 切换），前端实时渲染。
- **N4 执行安全**：Shell/代码执行的沙箱策略（工作目录约束、命令黑白名单、危险操作需前端确认——类似 Claude Code 的 permission 机制）。
- **N5 成本控制**：按 Session/用户/模型统计 Token 与费用，支持配额上限。

**建议 P1（二期）**
- **N6 Git 集成**：diff 预览、commit、分支管理、代码审查视图。
- **N7 审计日志**：谁在何时用什么模型执行了什么命令/工具。
- **N8 Agent 模板/编排自定义**：预置团队模板（如「规划→编码→审查」），支持用户自定义 Agent 角色、Prompt、工具集与编排方式（Chain/Parallel/Graph）。
- **N9 Knowledge/RAG**：项目文档/代码库知识检索（trpc-agent-go knowledge 模块）。
- **N10 评估（Evaluation）**：任务回放、A/B 对比不同模型/Prompt（trpc-agent-go evaluation 模块）。

**建议 P2（远期）**
- **N11 多租户/团队空间**、**N12 A2A 协议**（对外暴露 Agent 服务）、**N13 Hooks 机制**（工具调用前后钩子）、**N14 子 Agent 市场/分享**。

## 3. 总体架构

```
┌─────────────┐  ┌─────────────┐
│  Web (Vue3) │  │  CLI (Go)   │        ← 两端复用同一 API
└──────┬──────┘  └──────┬──────┘
       │  REST + SSE (OpenAPI 契约)
┌──────┴─────────────────┴──────────────────────────┐
│              API Gateway (Gin/tRPC-Go)             │
│   Auth(JWT/APIKey) · RBAC · 审计 · 限流            │
├────────────────────────────────────────────────────┤
│                  应用服务层                         │
│  SessionSvc │ AgentSvc │ ProviderSvc │ ToolSvc     │
│  SkillSvc   │ McpSvc   │ CommandSvc  │ ObserveSvc  │
├────────────────────────────────────────────────────┤
│           Agent 引擎层（trpc-agent-go）             │
│  Runner · LLMAgent/Chain/Parallel/Graph · Planner  │
│  Tool/MCP · Session/Memory · Knowledge · Telemetry │
├────────────────────────────────────────────────────┤
│  存储层：GORM(SQLite3 → MySQL/PG) · 文件工作区      │
│  可观测：OpenTelemetry → 本地存储/OTLP 导出         │
└────────────────────────────────────────────────────┘
```

**关键设计决策**
1. **存储抽象**：全部走 GORM + Repository 接口，SQLite3 仅是 driver，切库零改动业务代码（trpc-agent-go 自带 storage/gorm 与 session/memory 的 SQLite 后端，直接复用）。
2. **API 优先**：先定 OpenAPI 契约，Web 与 CLI 都是消费者；CLI 后期用 Go 写（cobra + bubbletea），可复用后端 SDK。
3. **事件流协议**：后端将 trpc-agent-go 的 Event 流转换为统一 SSE 事件（message_delta / tool_call / tool_result / agent_transfer / done / error），前端与 CLI 共用。
4. **斜杠命令引擎在后端**：命令注册表由后端下发（含参数 schema），前端只做补全 UI，保证 Web/CLI 行为一致。

## 4. 核心模块规划

### 4.1 后端（Golang）
```
server/
├── cmd/server/          # 入口
├── internal/
│   ├── api/             # HTTP handler + SSE
│   ├── auth/            # JWT、APIKey、RBAC
│   ├── service/         # 应用服务层
│   ├── engine/          # trpc-agent-go 封装：Runner 池、Agent 工厂、事件转换
│   ├── provider/        # LLM Provider 管理 + /v1/models 自动发现 + Key 加密(AES-GCM)
│   ├── tools/           # 内置工具集（file/shell/grep/git/http…）+ 权限确认机制
│   ├── skills/          # SKILL.md 解析、注册、加载
│   ├── mcp/             # MCP 客户端生命周期管理、工具发现
│   ├── command/         # 斜杠命令注册表与执行器
│   ├── observe/         # OTel 接入、trace 存储、token/成本统计
│   ├── repo/            # Repository 接口 + GORM 实现
│   └── model/           # 领域模型
└── pkg/apiclient/       # Go SDK（CLI 复用）
```

### 4.2 数据模型（首期）
`users` `api_keys` `providers` `models` `workspaces` `sessions` `messages` `agent_runs` `tool_calls(审计)` `tools_config` `skills` `mcp_servers` `commands` `usage_stats` `settings`

### 4.3 前端（Vue3 技术栈）
- Vue 3 + TypeScript + Vite + Pinia + Vue Router + Naive UI（或 Element Plus）+ UnoCSS
- 页面：对话工作台（核心，含斜杠命令面板/工具调用卡片/diff 视图）、Workspace 管理、Agent 编排配置、Provider&Model 管理、Tools/Skills/MCP 管理、可观测面板（Trace 瀑布图、Token 统计）、系统设置

### 4.4 多 Agent 协作预置模板（基于 trpc-agent-go）
- **CodeTeam（默认）**：Orchestrator(GraphAgent) → Planner → Coder ⇄ Reviewer → Tester，失败回环
- **QuickChat**：单 LLMAgent + 全量工具（轻量模式）
- **ResearchTeam**：Parallel 检索 + 汇总
- 用户可基于模板自定义角色 Prompt、模型、工具集、编排拓扑

### 4.5 斜杠命令（首期清单，参考 Claude Code）
`/help` `/clear` `/compact` `/model <name>` `/agents` `/tools` `/mcp` `/skills` `/memory` `/init`（生成项目 AGENT.md） `/review` `/commit` `/cost` `/export` `/config` `/status`

## 5. 里程碑

| 阶段 | 内容 | 出口标准 |
|------|------|----------|
| **M0 骨架** | 项目脚手架、DB/GORM、Auth、Provider/Model 管理（含自动拉取）、单 Agent 对话 + SSE 流式 | Web 上能选模型完成流式对话 |
| **M1 CodeAgent 核心** | 内置工具集 + 权限确认、Workspace/Session、多 Agent CodeTeam、斜杠命令引擎 | 能在工作区完成一次「需求→编码→文件落盘」任务 |
| **M2 生态扩展** | MCP 管理、Skills 管理、Agent 编排自定义、Git 集成 | 外接 MCP 工具可被 Agent 调用 |
| **M3 企业化** | 可观测面板（Trace/成本）、审计、配额、RBAC 完善 | Trace 可视化 + 成本报表可用 |
| **M4 CLI & 进阶** | Go CLI（cobra+bubbletea）、Knowledge/RAG、评估回放 | CLI 与 Web 功能对齐 |

## 6. 已确认决策（2026-07-28 评审）

| 决策点 | 结论 | 影响 |
|--------|------|------|
| 部署形态 | **一开始就多用户企业部署** | M0 即实现完整用户/角色/RBAC/JWT + APIKey；`users/roles` 表首期落地 |
| 执行安全 | **宿主机+确认 与 Docker 沙箱两者都要（可配置）** | 定义统一 `Executor` 接口：`HostExecutor`（默认，工作目录约束+危险命令确认）与 `DockerExecutor`（按 Workspace 配置启用）；M1 先落地 Host，M2 补 Docker |
| UI 组件库 | **Naive UI** | Vue3 + TS + Vite + Pinia + Naive UI + UnoCSS |
| LLM 协议 | **OpenAI + Anthropic + Gemini 三协议** | provider 模块做协议适配层：`protocol` 字段（openai/anthropic/gemini），模型自动发现分别对接 /v1/models、/v1/models(Anthropic)、models.list(Gemini) |
